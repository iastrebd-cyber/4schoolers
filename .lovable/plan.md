

# Выравнивание "97%" в Hero

## Проблема
Цифры "97%" визуально опускаются ниже базовой линии остального текста заголовка, и пользователь хочет, чтобы они были крупнее на 15% и выровнены по центральной горизонтальной оси основной строки.

## Изменения

**Файл:** `src/components/hero.tsx`

Обновить `<span>` вокруг "97%" в заголовке `<h1>`:

- Убрать `align-baseline` (именно он прижимает цифры к базовой линии шрифта, из-за чего визуально кажется, что они "ниже").
- Использовать `inline-flex items-center` на родительском `<h1>` не получится (это сломает перенос строк), поэтому применим к самому span трюк с вертикальным выравниванием через `inline-block` + отрицательный `translate-y` для оптической центровки по средней линии заглавных букв.
- Увеличить размер на 15% через `text-[115%]` (relative em-based scaling — масштабируется относительно родительского размера на всех брейкпоинтах: mobile/tablet/desktop).
- Сохранить красный цвет `text-[hsl(0_75%_45%)]`.
- Добавить `font-bold leading-none` для чистой оптики.

Итоговый span:
```tsx
<span className="inline-block text-[115%] leading-none text-[hsl(0_75%_45%)] -translate-y-[0.04em] align-middle">
  97%
</span>
```

`align-middle` совместно с лёгким `-translate-y` точно центрирует крупные цифры по горизонтальной оси x-height соседнего uppercase-текста на всех размерах экрана (включая текущий мобильный viewport 428px).

## Технические детали
- `text-[115%]` — Tailwind arbitrary value, наследует базовый `font-size` от h1 (5xl → 6xl → 7xl) и увеличивает только "97%" пропорционально на 15%.
- `-translate-y-[0.04em]` — em-единицы, поэтому смещение масштабируется вместе со шрифтом и работает идентично на всех брейкпоинтах.
- Никаких других файлов трогать не нужно.
